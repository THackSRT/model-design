# 12. Pile technique recommandée

Deux langages suffisent : TypeScript pour les applications et les services métier, Python pour les moteurs de calcul et l'IA.

| Couche                | Choix                                                                                        | Pourquoi                                                                                                                                                              | Alternative écartée                                                                             |
| --------------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Application mobile    | React Native (Expo) + base locale SQLite synchronisée                                        | Même langage que le web et les services : modèles de vue et types générés partagés ; hors-ligne par SQLite ; correctifs publiés sans repasser par les stores          | Flutter : rendu très fluide, mais Dart ajoute un langage et ne partage rien avec le web         |
| Web et studio         | React + TypeScript, three.js                                                                 | Le plus grand écosystème, le mieux connu des agents de codage ; three.js lit le glTF et tourne déjà dans le prototype                                                 | Vue : valable, mais sépare le web du mobile React Native                                        |
| Services métier       | Node.js + TypeScript, NestJS limité aux adaptateurs                                          | Services surtout en attente de la base et du bus, où Node suffit ; un seul langage de l'écran à la base ; NestJS impose la même structure partout                     | Go : plus sobre en mémoire, mais un troisième langage pour un gain faible sur ce type de charge |
| Moteurs de calcul     | Python 3.12 + FastAPI                                                                        | GarmentCode, NumPy, Warp et les bibliothèques d'IA sont en Python ; FastAPI produit l'OpenAPI depuis les modèles Pydantic                                             | Portage TypeScript : des mois pour réécrire ce qui existe                                       |
| Moteur mannequin      | TypeScript partagé navigateur et serveur                                                     | Ajustement en moins de 0,5 s sur le téléphone, sans réseau ; déjà prototypé                                                                                           | Python : un aller-retour serveur à chaque réglage                                               |
| Drapé                 | NVIDIA Warp                                                                                  | Simulation GPU écrite en Python, désormais sous licence Apache 2.0 : le point de licence est levé                                                                     | Simulateur maison : coûteux. Limite acceptée : Warp lie le drapé aux GPU NVIDIA                 |
| IA                    | Passerelle vers des modèles par API + modèles ouverts auto-hébergés (vLLM)                   | Les meilleurs modèles par API pour le texte et l'image ; auto-hébergés pour les photos du corps, qui ne sortent pas                                                   | Fournisseur unique : plus simple, mais dépendance et photos envoyées dehors                     |
| Base de données       | PostgreSQL                                                                                   | Sécurité au niveau des lignes pour isoler les organisations, JSONB pour les spécifications de patron, service managé partout                                          | NoSQL : perd les transactions et la sécurité par lignes dont le métier a besoin                 |
| Cache                 | Valkey                                                                                       | Même protocole que Redis, licence BSD, gouvernance Linux Foundation                                                                                                   | Redis : Redis 8 est sous RSAL, SSPL ou AGPL, ce qui impose une revue juridique                  |
| Stockage objet        | Compatible S3                                                                                | Standard, URL signées, proposé par tous les clouds                                                                                                                    | —                                                                                               |
| Bus et file de tâches | NATS JetStream                                                                               | Un seul composant pour les événements, les files de tâches et les permissions par sujet ; léger à opérer ; reste sous Apache 2.0 à la CNCF après le différend de 2025 | Kafka : fait pour de très gros débits, plus lourd à opérer. RabbitMQ : pas de rejeu des flux    |
| Orchestration         | Kubernetes managé                                                                            | Nécessaire pour 23 déploiements séparés, un maillage et des politiques réseau                                                                                         | Service de conteneurs sans Kubernetes : plus simple, sans maillage ni politiques fines          |
| Maillage de services  | Istio en mode ambient                                                                        | mTLS et politiques d'accès sans proxy dans chaque pod, stable depuis Istio 1.24, entièrement libre                                                                    | Linkerd : plus simple, mais ses versions stables sont payantes au-delà de 50 employés           |
| Dépôt et outillage    | Monorepo pnpm + Nx (TypeScript) et uv (Python), générateurs, code généré depuis les contrats | Graphe des projets, frontières vérifiées, générateurs : ce qui garde les agents dans le cadre                                                                         | Turborepo : plus simple, sans frontières ni générateurs                                         |
| Accès aux données     | Drizzle ORM                                                                                  | Requêtes typées proches du SQL, migrations versionnées, compatible avec la sécurité par lignes                                                                        | Prisma : plus d'abstraction, plus loin du SQL                                                   |
| Contrats              | OpenAPI 3.1, AsyncAPI 3, JSON Schema                                                         | Standards ouverts, générateurs pour TypeScript et Python                                                                                                              | gRPC : efficace, mais moins pratique pour le web, le mobile et les webhooks                     |
| Paiements             | CinetPay, PayDunya, Flutterwave ou Paystack selon les pays                                   | Un contrat couvre plusieurs opérateurs de mobile money                                                                                                                | Intégration directe Wave et Orange Money : frais plus bas, mais un contrat par opérateur        |
| Messagerie externe    | API WhatsApp Business, SMS de secours, notifications push                                    | Là où sont déjà les clients et les ateliers                                                                                                                           | —                                                                                               |
| Observabilité         | OpenTelemetry, Grafana, Sentry                                                               | Standard ouvert, pas d'enfermement chez un fournisseur                                                                                                                | Datadog : complet, mais cher à l'échelle                                                        |

**Est-ce le meilleur choix ?** Aucune pile n'est la meilleure dans l'absolu ; celle-ci est le meilleur compromis pour nos contraintes : petite équipe, développement avec des agents, mobile hors-ligne, calcul 3D en Python, licences utilisables commercialement. La vérification des licences en septembre 2026 a corrigé trois choix : Valkey remplace Redis, Istio en mode ambient remplace Linkerd, et NATS sert aussi de file de tâches. Le choix le plus discutable reste les microservices dès le départ pour une petite équipe ; la pile en limite le coût, sans le supprimer.
